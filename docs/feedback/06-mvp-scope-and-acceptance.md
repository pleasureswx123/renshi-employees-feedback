# 首期范围与验收标准

## 1. 首期必须交付

### 1.1 平台基础

- 通过PC浏览器使用RuoYi账号登录。
- 获取当前用户、角色和权限。
- HR与员工工作台按权限展示。
- 未授权接口由后端拒绝。

### 1.2 HR评价项目

- 创建、编辑和删除准备阶段项目。
- 编辑问卷标题、说明、页面和五种题型。
- 问卷说明全卷共用；分页仅包含标题、顺序和题目，不编辑或展示页面说明。
- PC实时预览按页切换，页码位于通栏分隔线上方；每页均显示问卷标题与说明，试填内容不写入草稿或正式答案。
- 设置必答、选项分数、题目分数范围和问答限制。
- 新增指标、设置权重、绑定题目。
- 配置被评价人、评价人和评价关系。
- 发布前完整性校验。
- 发布后冻结版本并生成任务。

### 1.3 员工答题

- 我的待办列表和项目详情。
- 按被评价人逐人答题。
- 分页、上一页和下一页。
- 暂存不完整答案。
- 提交前必答校验和二次确认。
- 提交后不可修改。
- 我评价的只读查看。

### 1.4 进度与完成

- HR查看应完成、已提交、已暂存和未开始数量。
- 查看评价人、被评价人、关系和任务状态。
- HR手动完成项目。
- 未完成任务关闭，不能继续作答。

### 1.5 基础计分和报告

- 后端计算原始分、指标百分制、关系得分和个人总分。
- 展示完成率和缺失关系。
- 在系统内以网页表格展示团队排名、团队明细、个人指标、题目明细和自评/他评对比。
- 区分关系“不适用”和“已配置但未提交”，并展示原配置权重和实际参与计算权重。

## 2. 首期不交付

- 手机浏览、手机作答及手机预览；不提供独立电脑/手机预览弹窗。
- 问卷模板、模板库和复制模板创建。
- Excel导入和报告Excel导出。
- CSV及其他文件形式的报告导出。
- 强制分布。
- 去最高分、去最低分。
- 复杂图表和人才分析。
- 公开链接、二维码、小程序和无登录参评。
- 邮件和短信通知。
- 自动推断组织评价关系。
- 项目自动结束或完成后重新打开。
- 被评价人员工端个人报告。

## 3. 核心验收场景

### 场景A：完整闭环

1. HR创建项目并配置两名被评价人。
2. HR配置问卷、指标、关系和评价人。
3. 发布成功并生成正确数量的任务。
4. 员工登录后看到待办。
5. 员工先提交第一人，第二人仍可继续填写。
6. 员工提交第二人后项目进度更新。
7. HR手动完成项目并看到正确报告。

### 场景B：暂存与恢复

1. 员工填写部分答案并暂存。
2. 重新进入后恢复草稿。
3. 必答题未完成时不能正式提交。
4. 补充完成后只产生一份提交答卷。

### 场景C：有未完成任务时结束

1. 项目存在已提交、已暂存和未开始任务。
2. HR完成时看到准确统计和警告。
3. 确认后未提交任务变为已关闭未完成。
4. 员工不能继续作答。
5. 报告只统计已提交答卷并展示完成率。

### 场景D：权限隔离

1. 普通员工不能访问HR项目接口。
2. 员工不能读取其他评价人的答卷。
3. 修改前端请求中的用户ID不能越权。
4. HR数据范围按角色和部门生效。

### 场景E：不可变性和并发

1. 发布后不能修改冻结配置。
2. 提交后不能修改答案。
3. 重复点击提交不会产生重复答卷。
4. 两个并发提交请求最多一个成功写入。

### 场景F：缺失关系、报告权限和交付形式

1. 同一项目中，一名被评价人没有下级评价任务，另一名被评价人有下级任务但项目完成时未提交。
2. 报告把前者标记为“下级不适用”，不计入应完成任务；把后者标记为“下级缺失”，计入未完成任务。
3. 两人的综合分分别按各自实际已提交计分关系的原配置权重重新归一化，并展示实际参与权重。
4. 只有`feedback:report:view`的HR可以查看汇总报告，但不能查看原始答案。
5. 额外具有`feedback:answer:view`且数据范围匹配的HR只能查看已提交原始答案，不能查看草稿。
6. 报告只在系统内以网页表格呈现，不出现Excel、CSV下载按钮或对应导出接口。

## 4. 验证门槛

- 后端实体、服务和API有直接测试。
- 前端题型、表单校验和状态Store有直接测试。
- 核心闭环至少有一条真实浏览器端到端测试。
- PostgreSQL迁移能在独立空库升级成功。
- 构建、格式检查和相关测试通过后，才能声明该阶段完成。
