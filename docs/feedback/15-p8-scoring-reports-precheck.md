# P8 计分与基础报告实施契约

## 1. 范围与状态

2026-09-03 已完成 P8 实现与阶段验收。本文第 2 至 4 节是实现契约，第 6 节记录直接验证证据；该结论限于已迁移的独立开发/测试环境，不代表通过 P9 上线验收。

- 复用冻结问卷、关系、任务、已提交答卷、`fb_score_result` 和 RuoYi 双层数据范围。
- 后端纯计算器 → 服务层事务 → PostgreSQL 结果和依据 → HR 网页表格。
- 不开放员工个人报告，不提供导出，不改变完成项目状态机。

## 2. 计分与精度

- 使用 `Decimal`，局部计算上下文精度为 50 位有效数字；中间步骤不按展示位数量化。循环小数受该上下文精度约束。
- `fb_score_result.score/effective_weight` 通过 P8 迁移改为 PostgreSQL 无固定小数位的 `NUMERIC`，完整保存计算器输出；原始题分与配置权重继续使用已有四位小数协议。
- 对外分数、权重、完成率均由后端 `ROUND_HALF_UP` 显示两位小数；排序使用未量化的持久化总分，相同正式分数并列（1、1、3），同分按被评价人 ID 升序，空分置后且不排名。只在当前可见范围内排名，姓名筛选不改变该范围排名。
- 每份答卷按全部绑定计分题最高分之和作为指标分母。已提交答卷漏答可选计分题时，分母不减少、该题不增加分子，同时记录漏答数量；不补写零分答案。题目明细的均分仅对实际有答案者计算，并显示漏答数量。没有已提交答卷的关系仍为空，不能当零分。
- 同关系多人先分别算指标分再平均；按已提交计分关系原权重归一化。自评只作对照，只有发布目标的 `only_self_evaluation` 为真时才按自评 100% 计入总分。非计分关系只展示。
- 正式总分按冻结指标权重合成；缺少有效正式关系时为空并显示“数据不足”。自评分和他评分分别展示，不互相填补。
- 校验输入版本、冻结规则版本、指标/关系权重快照、已提交状态、题分及提交快照一致性；不一致时拒绝生成，不能忽略损坏答卷。

## 3. 生成与不可变依据

- `POST /feedback/projects/{id}/reports/calculate`：权限 `feedback:report:view`，仅已完成项目可用。进入报告页先查询正式报告，尚未就绪时自动调用此接口，生成当前数据范围内可见目标的全部结果；已有报告直接展示。失败停止自动尝试，显示错误并提供手动重试；离页或切换项目后忽略迟到响应。仍使用独立POST接口，不把写入放入GET，也不改变HR手动完成项目的规则。
- 按项目排他锁串行化生成，锁内校验完成状态与项目/目标范围；同一事务写入关系指标、综合指标、个人总分和覆盖率。
- 已有完整结果返回幂等成功，不更新结果、依据或计算时间。部分结果、未知计算版本返回冲突；失败全部回滚。不提供覆盖重算入口。
- `calculation_basis` 保存计分器版本、发布规则、冻结题目/指标/关系、目标仅自评标记、任务集合、已提交答卷 ID/摘要/题分，以及中间值。个人结果同时保存不含身份和原文的报告投影；查询不把内部依据暴露给报告权限。
- P8 精度迁移保留既有结果；降级若会损失任一结果精度必须拒绝，禁止静默四舍五入。
- 生成前核验结果字段实际精度；旧表返回 `REPORT_SCHEMA_NOT_READY`，禁止依靠 ORM 类型声明把完整精度结果写入仍为四位小数的数据库。

## 4. 查询、权限与页面

| 接口 | 权限 | 内容 |
|---|---|---|
| `GET /feedback/reports/projects` | `feedback:report:view` | 可见已完成项目，支持名称筛选和分页；不依赖项目列表权限 |
| `GET /feedback/projects/{id}/reports` | `feedback:report:view` | 是否已生成、范围说明、完成率、团队排名/指标/自评/他评 |
| `GET /feedback/projects/{id}/reports/{target_user_id}` | `feedback:report:view` | 个人指标、关系原/实际权重、不适用/缺失、题目汇总 |
| `GET /feedback/projects/{id}/answers` | `feedback:answer:view` | 已提交答卷列表，可按被评价人筛选；不返回草稿 |
| `GET /feedback/projects/{id}/answers/{assignment_id}` | `feedback:answer:view` | 已提交原始答案、评价人快照与只读问卷；不依赖报告权限 |

- 每个接口必须同时检查项目归属范围和发布时被评价人部门范围；全部目标不可见、指定目标/答卷不可见统一 404。
- 沿用 RuoYi 权限依赖的 `HTTP 200 + code=403` 拒绝信封；资源范围错误使用 HTTP 404，未完成项目和数据冲突使用 HTTP 409。前端统一请求层按业务码处理拒绝。
- 局部范围只返回可见人员、数量、分数和排名，明确提示不能代表全项目。查询不按评价人当前部门过滤。
- 报告响应不包含评价人 ID/姓名、答卷 ID、选项选择、附加原因、问答原文、答案摘要或内部计算依据。原始答案是单独请求，不预取。
- 报告与答案访问通过 RuoYi 操作日志记录元数据，禁用完整响应/答案内容日志。响应加 `Cache-Control: no-store`。
- 路由 `/hr/reports`、`/hr/projects/:projectId/reports`、`/hr/answers`、`/hr/projects/:projectId/answers`。报告入口支持仅报告权限账号；原始答案入口支持单独答案权限。
- 使用 Element Plus 表格、表单校验、抽屉和只读题型组件，Pinia 保存会话内状态。切换项目、目标、退出或权限错误时清除旧数据并丢弃过期响应。

### 得分来源与核对

- 关系分详情在具备原始答案权限时自动按需加载逐份依据，按每份答卷分组展示绑定题目实得分/满分、两组求和式、百分制换算式，最后列出所有有效答卷指标分的逐项平均公式。无权限时保留汇总公式和权限提示，不请求逐份依据。

- 点击最终得分、指标最终得分或关系分打开“得分来源”，按最终得分 → 指标加权 → 关系平均 → 答卷换算 → 题目得分追溯。
- `GET /feedback/projects/{id}/reports/{target}/source` 沿用报告权限与项目/目标双层范围，输出公式、结果、未舍入结果及说明的白名单投影，不返回内部依据、答卷标识、身份或原始回答。
- `GET /feedback/projects/{id}/reports/{target}/source/sheets?indicatorId=...&relationId=...` 同时要求报告和原始答案权限，只按需输出所选关系的匿名答卷换算与绑定题目原始题分、满分、漏答说明。不会返回选项选择、文字回答、摘要或内部 ID。
- 使用原版本计分器对 PERSON_TOTAL 保存的冻结输入做只读复核，与持久化总分及报告投影比较一致后输出解释。未知版本、缺失或不一致依据返回 409，不能伪造公式或覆盖正式结果。无数据库迁移，无重新生成或持久化写入。
- 汇总公式取未舍入数值，结果展示两位小数；可查看完整未舍入结果。关系平均以指标分之和除有效已交份数，逐份明细再展示实得分合计 / 满分合计 × 100；可选题漏答不减少分母。
- 两个接口响应均为 no-store，日志不记录正文；关闭、切换项目或目标后清除公式数据并丢弃迟到响应。

### 已提交答卷入口

- 列表和详情展示“答卷原始总分”，取已提交答卷保存的 `raw_total_score`，表示全部计分题得分之和，不进行百分制换算或指标、关系加权。保持原始精度，显示去除末尾零；零分和缺失分数分别展示。

- 菜单、面包屑与页面统一称为“已提交答卷”，用于查看实际提交的选项、打分与文字回答及评价人身份，只读且保留访问审计。
- 入口按项目名称远程搜索，不要求手工填写项目 ID。`GET /feedback/answers/projects` 使用 `feedback:answer:view` 及项目/目标双层数据范围，分页返回进行阶段和已完成项目，支持名称搜索及按 ID 解析已有项目链接。无需项目管理或报告权限。
- 未选择项目时提示先选项目；读取失败和项目没有已提交答卷分别展示，不混为无记录。报告入口带入项目，已完成项目可跳转报告。

### 报告展示口径

- 增加 ECharts“得分图表”页签，横向条形图同时展示最终得分与全部指标：最终得分占一行，指标卡片宽屏双列、窄屏单列，不再下拉切换。统一 0–100 分刻度，沿用服务端顺序，不重算或改变排名。
- 图表明确只覆盖当前页及当前筛选，缺失数据不补零；提示部门、完成份数及仅自评口径，条形点击与键盘人员选择均可打开得分来源。兼容主题和容器尺寸变化，离页释放图表；图表依赖按页签懒加载。

- 项目报告提供“团队排名”和“指标对比”两个页签，共用服务端姓名筛选、分页和排名。排名页得分条统一采用 0–100 分刻度，仅用于展示，不在前端重新计分或重排。
- 指标对比默认使用两级表头，一行一人：左侧为部门、被评价人、总得分、上级、同级、自己；随后按实际冻结指标分组，一级表头保留加粗指标名称及权重（如“指标1 权重 20.00%”），二级表头为上级、同级、自己、综合平均。项目存在其他关系时继续展示对应列，支持筛选单个指标。
- 左侧上级、同级、自己分别为全部指标对应关系得分之和 ÷ 指标数，不使用指标权重，筛选单个指标也不改变该汇总口径。由后端读取当前页人员已保存的精确指标关系结果，以 Decimal 计算后保留两位小数，接口通过 `relationScores` 返回；兼容已有报告，不覆盖保存的正式结果。任何指标缺分时返回空值，不将缺分当零分或减少分母；零权重指标也计入指标数。“综合平均”是既有指标最终加权得分的展示名称，不改为算术平均，不改变自评及正式计分规则。
- 表格保留异常提交和漏答提示，悬停或聚焦指标分数可查看覆盖率及实际权重。部门、被评价人和总得分列固定，表头固定，宽表横向滚动；未配置关系显示横线，未提交显示数据不足，零分仍展示零分。
- 左侧各关系平均分支持点击查看得分来源：展示全部指标关系分的算术平均公式、未舍入结果与各指标来源；有原始答案查看权限时可继续按指标查看答卷和题目依据。指标下的关系表头以小字展示发布时配置的原权重，个人实际权重仍在分数提示中展示。
- 报告筛选采用 `ElForm size="small"`，被评价人、查看维度、部门和排序在同一行展示，窄屏自动换行。部门按发布时部门名称快照精确筛选，选项来自当前数据范围全部目标；指标和关系选项来自冻结配置，不受当前页或空结果影响。
- 总得分及各关系跨指标平均分均可升序或降序，默认总得分降序。后端在分页前执行筛选与排序，按未舍入分数排序，缺分始终置后，同分按人员 ID 稳定排列；排名编号仍按可见范围总得分计算，不随筛选或展示排序改变。每页支持 10、20、30、50、100 条，查询和切换每页条数回到第一页。
- 维度和关系按 ID 对齐，数据取自当前分页报告，不批量请求个人详情。计分说明为只读，个人详情仍保留冻结权重与题目明细；不添加导出，不改动既有测试项目名称。

- 团队主表将 `score` 命名为“最终得分”，用于排名；`selfScore` 命名为“自评参考分”。主表不重复展示他评分和指标分，统一通过“查看得分详情”查看。
- 普通人员明确提示“按他评加权计分”，自评不参与最终得分；发布时仅配置自评的人员逐行标注“仅自评 · 以自评计分”，避免误解为所有自评都只作参考。
- 最终得分为空时，按发布时仅自评标记区分“自评数据不足”与“他评数据不足”，不以自评兜底他评，不将零分显示为空。
- 详情保留他评加权分、指标得分、关系实际权重和题目明细，并解释计算顺序。仅调整展示名称和信息层级，后端字段、公式、排名和历史结果保持原有契约。
