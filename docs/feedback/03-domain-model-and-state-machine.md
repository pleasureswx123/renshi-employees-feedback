# 领域模型与状态机

## 1. 聚合边界

### 1.1 评价项目

负责项目状态、创建者、发布信息、完成信息和当前问卷版本。

### 1.2 问卷版本

负责页面、题目、选项、指标、指标权重、题目绑定、关系配置和计分配置。

### 1.3 评价任务

负责评价人、被评价人、评价关系、任务状态、暂存和提交时间。

### 1.4 答卷

负责某一评价任务下的题目答案、原始得分和提交快照。

### 1.5 计算结果

负责关系得分、指标得分、个人总分、完成覆盖率和计算依据。

## 2. 项目状态机

```text
PREPARING（准备阶段）
        │ 发布
        ▼
ACTIVE（进行阶段）
        │ HR手动完成
        ▼
COMPLETED（已完成）
```

约束：

- 只有准备阶段允许编辑或删除项目草稿。
- 发布必须通过完整性校验。
- 进行阶段禁止修改已冻结配置。
- 只有进行阶段可以手动完成。
- 首期不支持从已完成回到进行阶段。

## 3. 任务状态机

```text
PENDING（待评价）
   │ 保存草稿
   ▼
DRAFT（已暂存）
   │ 提交
   ▼
SUBMITTED（已提交）

PENDING / DRAFT
   │ HR完成项目
   ▼
CLOSED_INCOMPLETE（已关闭未完成）
```

约束：

- `SUBMITTED` 和 `CLOSED_INCOMPLETE` 是终态。
- 提交必须校验所有必答题。
- 同一任务只能成功提交一次。
- 重复提交请求应返回已有提交结果或明确的冲突错误，不能生成第二份答卷。
- 暂存允许答案不完整。

## 4. 业务唯一性

评价任务业务唯一键：

```text
project_id + evaluator_user_id + target_user_id + relation_id
```

单题答案业务唯一键：

```text
answer_sheet_id + question_id
```

选项附加原因与主答案一起保存，不建立第二份独立答卷。

## 5. 问卷顺序

- 页面具有 `sort_order`。
- 题目在页面内具有 `sort_order`。
- 展示题号由页面顺序和题目顺序动态计算，不永久保存“第N题”文本。
- 复制、移动或删除题目后重新计算展示序号。

## 6. 计分基线

正式报告统一换算为百分制，原始题目分值保留。

### 6.1 单份答卷指标分

```text
指标分 = 指标下计分题实际分之和
       ÷ 指标下计分题最高分之和
       × 100
```

问答题不参与数值计算。

### 6.2 评价关系得分

```text
关系得分 = 同一被评价人、同一关系下已提交答卷指标分的平均值
```

### 6.3 指标综合得分

```text
实际参与权重(r) = 原配置权重(r)
                 ÷ 所有存在已提交答卷的计分关系原配置权重之和

指标综合得分 = Σ[关系得分(r) × 实际参与权重(r)]
```

关系权重规则：

- 不提供组织级默认权重，由HR在项目准备阶段配置并在发布时冻结。
- 项目存在非自评任务时，自评配置权重为0，只用于对照；参与综合分的非自评关系原配置权重必须精确合计为`100.0000`。
- 某关系对某个被评价人没有任何评价任务时，该关系对该人“不适用”，不进入权重分母。
- 某关系已经生成任务但没有已提交答卷时，该关系为“缺失关系”，不按0分处理，也不进入实际参与权重分母。
- 只有发布时某个被评价人确实仅配置自评任务时，自评才按100%计算。不能在他评全部缺失时用自评兜底替代正式他评综合分。

### 6.4 个人总分

```text
个人总分 = 各指标综合得分按指标权重合成
```

数据库计算过程至少保留四位小数，展示保留两位小数。

### 6.5 缺失关系

HR在仍有未提交任务时完成项目，报告只使用有已提交答卷的关系，并按实际参与关系的原配置权重重新归一化。报告必须分别标明：

- 不适用关系：发布时未为该被评价人生成该关系的任务，不进入应完成数量。
- 缺失关系：发布时已经生成任务，但项目完成时该关系没有已提交答卷。
- 原配置权重：发布快照中的项目关系权重。
- 实际参与权重：对当前被评价人、当前指标重新归一化后的权重。
- 任务完成率：已提交任务数除以发布时生成的全部任务数。

若不存在任何可参与正式计分的已提交关系，则正式综合分为空并标记“数据不足”，不得保存为0分。

### 6.6 手工计分样例

以下样例只展示一个指标，关系得分均已完成“同一关系多人平均”。正式实现统一使用`Decimal/NUMERIC`计算，中间过程至少保留四位小数。

#### 样例A：全部关系完成

```text
原配置权重：上级50%，同级30%，下级20%
关系得分：上级90，同级80，下级70

指标综合得分
= 90×50% + 80×30% + 70×20%
= 83.00
```

#### 样例B：某关系对该员工不适用

项目配置上级50%、同级30%、下级20%，但该被评价人发布时没有下级评价任务。上级和同级均已提交。

```text
适用关系原权重之和 = 50 + 30 = 80
上级实际参与权重 = 50 ÷ 80 = 62.5%
同级实际参与权重 = 30 ÷ 80 = 37.5%

指标综合得分
= 90×62.5% + 80×37.5%
= 86.25

下级标记：不适用
任务完成率：100%
```

#### 样例C：有关系任务但未提交

上级、同级、下级任务均已生成；上级和同级已提交，下级在项目完成时未提交。假设每个关系各一份任务。

```text
已提交关系原权重之和 = 50 + 30 = 80
上级实际参与权重 = 62.5%
同级实际参与权重 = 37.5%

指标综合得分
= 90×62.5% + 80×37.5%
= 86.25

下级标记：缺失关系
任务完成率：2 ÷ 3 = 66.67%
```

#### 样例D：发布时仅有自评

```text
自评关系得分：92
自评实际参与权重：100%
指标综合得分：92.00
```

## 7. 发布完整性校验

至少校验：

- 项目标题有效。
- 问卷至少有一页和一道有效题目。
- 所有计分题最高分大于零。
- 所有必答题配置完整。
- 至少存在一名被评价人。
- 指标权重总和为100%。
- 所有计分题已绑定指标。
- 项目存在非自评任务时，所有启用且参与综合分的非自评关系原配置权重精确合计为`100.0000`，自评配置权重为0。
- 每名被评价人至少存在一份评价任务；允许某个项目关系对部分被评价人不适用。
- 每个权重大于0的非自评关系至少对项目中的一名被评价人生成任务，避免保留完全无效的权重配置。
- 某被评价人没有非自评任务时，只允许其存在自评任务，并在发布快照中明确记录“仅自评”。
