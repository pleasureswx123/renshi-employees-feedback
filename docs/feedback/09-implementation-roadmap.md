# 分阶段实施路线图与可执行任务清单

## 1. 文档目的

本路线图用于指导员工反馈与 360° 评价平台首期实施。它不是简单的功能列表，而是编码、数据库迁移、联调、测试和验收共同遵守的阶段门禁。

阶段编号表示依赖顺序，不表示自然周。没有确认人员投入前，不在本文件中承诺具体工期。

首期固定工程边界：

- `ruoyi-fastapi-backend`：唯一后端，新增核心业务模块 `module_feedback`。
- `ruoyi-fastapi-frontend`：系统管理端，只负责账号、组织、角色、菜单、字典和运维。
- `feedback-frontend`：评价业务平台，包含 HR 工作台和员工工作台。
- PostgreSQL：唯一正式业务数据库。

## 2. 实施原则

### 2.1 垂直切片优先

优先完成能够真实闭环的小功能：

```text
页面操作
→ 后端校验
→ PostgreSQL持久化
→ 重新进入恢复
→ 权限校验
→ 自动化测试
```

不能把静态页面、内存演示或 Mock 数据视为阶段完成。

### 2.2 阶段门禁

- 同一时间只推进一个主阶段，修复前序阶段缺陷除外。
- 当前阶段的退出条件全部满足后，才能进入下一阶段。
- 若业务规则发生变化，先更新产品、领域、数据库和验收文档，再修改代码。
- 每个阶段只创建当前任务实际需要的文件，不批量创建未来空目录和空类。

### 2.3 生成器使用边界

- RuoYi 代码生成器只用于简单表的 DO、VO、DAO、基础 CRUD、权限码和菜单 SQL 参考。
- 必须先预览或生成到临时目录，再逐文件选择性集成。
- 问卷设计器借鉴现有表单构建器的组件面板、拖拽画布、属性面板和组件注册思路，但重新实现业务数据结构和渲染器。
- 发布冻结、任务生成、逐人提交、幂等控制、计分和报告必须手写领域逻辑。

### 2.4 首期明确不做

- 问卷模板、模板库和复制模板创建。
- Excel 导入。
- 强制分布、去最高分和去最低分。
- 复杂图表和人才分析。
- 公开链接、二维码、小程序和无登录参评。
- 邮件、短信等外部通知。
- 自动推断上级、同级和下级关系。
- 项目自动完成和完成后重新打开。

## 4. 通用完成标准

每个任务只有同时满足以下条件才能勾选完成：

- 实现位于约定工程和分层中，没有创建平行账号、组织或权限体系。
- 后端状态和正式分数由服务层及数据库约束保护，不能只依赖前端按钮状态。
- 数据库变更包含 Alembic 迁移、中文注释、必要约束和索引。
- API 包含鉴权、权限码、参数校验、错误语义和操作日志。
- 前端包含加载、禁用、防重复提交、失败提示和权限错误处理。
- 直接相关测试通过；不能运行的测试明确记录原因。
- 用户可见流程经过真实浏览器验证，不只依赖静态检查。
- 对应产品、数据、API或验收文档已经同步更新。
