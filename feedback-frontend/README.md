## 本地命令

```powershell
npm install
npm run dev
npm test
npm run build
npm run test:e2e
```

开发服务默认把 `/dev-api` 代理到 `http://127.0.0.1:9099`。如需连接其他本地后端，可通过进程环境变量 `VITE_APP_PROXY_TARGET` 覆盖代理目标。

## P6真实端到端验收

前提：PostgreSQL/Redis基础设施已启动，后端项目`.venv`已安装运行依赖和`requirements-test.txt`；隔离库`ruoyi_feedback_test`已升级到Alembic head。开发库不能用于下列测试。

```powershell
# 在本目录运行；自动启动后端9097和前端5177，不复用占用端口的服务
npm run test:e2e:live
```

- 使用完整RuoYi应用、真实登录/权限与PostgreSQL；不拦截业务API。
- 为临时HR、员工和两个被评价人生成账号/角色/项目，发布4项任务（2项他评、2项自评），员工逐人提交2项他评。
- 核验不完整暂存、页码/答案恢复、错误定位、手机与长文本、独立提交、历史只读、权限路由、退出保护及数据库逐条对账。
- 使用Redis逻辑库3，临时关闭测试验证码，测试结束恢复原值；不修改`.env.dev`或开发库、不自动给现有账号授权。请勿与其他使用同一测试库/Redis 3的测试并行运行。
- 凭据仅写入后端`.tmp/p6-live-automated.json`，正常结束自动清理。若强制中断，先确认验收服务已停止，再在后端目录执行`python scripts/feedback_p6_e2e_fixture.py cleanup --state .tmp/p6-live-automated.json`；脚本核验项目/账号/角色身份后仅清理本夹具。
- 页面截图写入仓库`output/playwright/`，不提交凭据、浏览器快照或运行产物。真实验收不保存可能含Token的网络trace。

## 开发边界

1. 阅读[平台端开发规则](./AGENTS.md)和[项目文档索引](../docs/feedback/README.md)。
2. 复用后端的账号、组织、角色和权限体系，不在本工程重复建设。
3. 不直接导入 `ruoyi-fastapi-frontend/src` 源码；所需能力在本工程按兼容契约独立实现。
4. 业务表单使用 Element Plus 表单与校验，普通业务提交使用显式点击或回车处理器。
5. 首期只允许已登录用户从系统内待办参评，不提供公开链接、二维码、小程序、邮件或短信参评入口。

后续实现顺序和退出门禁以[分阶段实施路线图](../docs/feedback/09-implementation-roadmap.md)为准。
